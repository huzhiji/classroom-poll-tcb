### 问题1：学习报告分类正确率全是 100%（疑似统计 bug）
- 根因：报告 `aggregateStudent` 原逻辑把 `stu.history[].details` 全量累加。每次提交练习/考试都无条件 `push` 一条 `history`（submitExam/submitLaw/作业，三处均无去重），学生重复提交或先错后重练对，会把"练N次对N次"算成"N题全对"，导致 byCategory 正确率虚高（全100%）。
- 修复：改为 **last-attempt-wins**——同一道题只取时间窗内最近一次作答结果计入掌握度；同时新增 `rawAttempts`（原始提交条数）与报告级 `dataCheck`（rawAttempts vs dedupedQuestions + duplicateRate），教师端报告详情展示"统计自检"提示，重复率≥30% 标红。
- 文件改动：`lib/store.js`（aggregateStudent、buildReport、getAIConfig 默认值）、`public/teacher.html`（报告详情加自检提示、AI配置卡片加账号禁用警告）。
- 提交 ca7a3a1，已 push origin main（本次网络通，ECS 自动拉取重建）。

### 问题2：接入七牛云 AI（api.qnaigc.com，用户给的 key 即七牛 AI Token API）
- 用户说明：用的是**七牛云 AI 推理**（邀请基础奖励 500 万 Token、2 年有效期、一次性分配）。endpoint `https://api.qnaigc.com/v1` 兼容 OpenAI。
- 实测结论：用真实 key 调 `/v1/models`（连查询都不需 chat 权限）也返回 **HTTP 403 account_chat_banned**——属**账号层面**问题，不是 key 错/网络/模型 ID 错。
- 根因（查七牛官方 FAQ）：Q22 明确 `account_chat_banned` = 风控判定"非法注册/恶意机刷 AI 推理资源包奖励"被封禁；也可能未实名(Q21)或欠费(Q29)。解封需提交申诉(https://jsj.top/f/VlBX1F)证明非机刷。
- 即使解封，Q40 指出还要在控制台「API Key → 模型范围」手动添加模型 ID，否则报 not available in your assigned model groups。
- 模型名：七牛标准可用为 deepseek-v3 / deepseek-r1(满血671B) / qwen3-max 等；`deepseek-v4-pro-0813` 未必是有效 API model 参数（Q6 强调必须严格匹配模型广场显示的 ID，否则 503）。
- 处理：教师端 AI 配置提示已细化（封禁/实名/模型范围/模型广场核对）；getAIConfig 默认 model 改 `deepseek-v3`。

- 结论：**支持，且比七牛云更省心**。系统 AI 分析本就是 OpenAI 兼容 /v1/chat/completions 协议，本地 Ollama/LM Studio/vLLM 原生兼容，代码零改动即可接。
